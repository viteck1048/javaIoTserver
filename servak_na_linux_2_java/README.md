# Servak Java HTTP/HTTPS Server

A Java-based server application designed to handle web requests with support for IoT devices. This server is a central component of a multi-server system that also includes C++ based services.

## Key Features

- **HTTP/HTTPS Handling**: Processes standard web requests.
- **IoT Support**: Manages communication with IoT devices.
- **Embedded Web Server**: Includes support for serving static content and processing PHP scripts.
- **Reverse Proxy:** Modular handler system — each backend type (`PHP-FPM`, `UniProxy`, `OldServak`, `RelaysServer`, `BanResponse`, `AI_CHAT`) has its own handler class. `ReverseProxy.java` dispatches by request type; handlers are stateless utility classes. See `HANDLERS.md` for details.
- **AI Chat:** Proxy to an OpenAI-compatible LLM endpoint (`AiChatHandler`). Supports streaming, system prompt composition, single-flight concurrency guard.
- **MachineTime Forwarder:** `MachineTimeForwarder` collects runtime data from AVR relay devices and forwards it to the `esp8266_decoder` microservice, emulating the ESP8266 device protocol.
- **SSL Management**: Automatically handles SSL certificates, including creation and renewal (ACME-like functionality).
- **Flexible Configuration**: Server behavior is controlled via an `.ini` configuration file.
- **Database Integration**: Uses a database for data persistence, with automatic table initialization.
- **Comprehensive Logging**: Supports logging to both console and files with configurable levels.

## System Architecture

This project is part of a larger system consisting of multiple servers:
- **`servak_na_linux_2_java` (This Server)**: The main Java-based entry point.
- **`servak_na_winapi_relays`**: A C++ based server for managing relays.
- **`servak_na_linux`**: Another C++ based server component.

These servers are designed to be run together using the provided startup scripts.

## Requirements

- Java 11 or higher
- `tmux` (for Linux)

## How to Run

The system is designed to be managed as a whole using the scripts in the `strt-stp_srvrs_*` directories.

### On Linux

The `autorun_tmux.sh` script starts all servers in a `tmux` session, with each server running in its own window. This allows for easy monitoring and management.

1.  **Navigate to the script directory**:
    ```bash
    cd /path/to/servers/strt-stp_srvrs_linux/
    ```

2.  **Make the script executable**:
    ```bash
    chmod +x autorun_tmux.sh
    ```

3.  **Run the script**:
    ```bash
    ./autorun_tmux.sh
    ```
    This will create and attach to a `tmux` session named `autorun`. You can detach from the session using `Ctrl+b` then `d`.

### On Windows

The `start_servers.bat` script launches all necessary server components.

1.  **Navigate to the script directory**:
    ```batch
    cd C:\path\to\servers\strt-stp_srvrs_win\
    ```

2.  **Run the start script**:
    ```batch
    start_servers.bat
    ```

3.  **To stop all servers**, run:
    ```batch
    stop_servers.bat
    ```

## Project Structure

- `source/`: Java source code.
- `www/`: Root directory for the web server.
- `www_php/`: Directory for PHP scripts.
- `logs/`: Contains log files generated by the server.
- `res/`: Resource files.
- `compilAndRun.sh`: Script for compiling and running this specific Java server.
